# Seguimiento de solicitudes para Espectadores (#24)

Fecha: 2026-10-03. Investigación del código de Seerr **v3.5.0**, la versión fijada por la [Plantilla](../../stacks/seerr/compose.yaml), y de documentación oficial. No se han ejecutado pruebas de entrega de notificaciones ni de aislamiento entre Espectadores en una Instancia en vivo.

## Conclusión

La primera entrega puede aprovechar Seerr: activar **Web Push** una vez para la Instancia, pedir a cada Espectador que se suscriba desde su dispositivo y habilitar la sincronización de Radarr/Sonarr para mostrar el progreso que Seerr ya implementa. No hace falta email ni Telegram para recibir Web Push. Quedan huecos reales en v3.5.0: las solicitudes **autoaprobadas** y los **fallos de procesamiento** no generan un push dirigido al solicitante, y Seerr no genera avisos de búsqueda sin resultados ni de descargas atascadas. [Fuente: guía oficial de Web Push](https://docs.seerr.dev/using-seerr/notifications/webpush/); [código de destinatarios](https://github.com/seerr-team/seerr/blob/v3.5.0/server/entity/MediaRequest.ts); [tipos de eventos](https://github.com/seerr-team/seerr/blob/v3.5.0/server/lib/notifications/index.ts); [tracker](https://github.com/seerr-team/seerr/blob/v3.5.0/server/lib/downloadtracker.ts).

El porcentaje y la hora estimada solo existen mientras el elemento aparece en la cola de Radarr/Sonarr; por diseño del tracker, una solicitud en búsqueda sin descarga no tiene porcentaje. La hora es una estimación de la cola, no una promesa de disponibilidad en Jellyfin. [Fuente: `DownloadingItem` y lectura de colas](https://github.com/seerr-team/seerr/blob/v3.5.0/server/lib/downloadtracker.ts); [presentación](https://github.com/seerr-team/seerr/blob/v3.5.0/src/components/DownloadBlock/index.tsx).

## ¿Se puede ver el estado dentro de Jellyfin?

La Plantilla fija **Jellyfin 12.1**. Jellyfin advierte expresamente que los plugins compilados para 10.11 no cargan en 12.0 sin una nueva compilación. Además, los botones y paneles añadidos con JavaScript a **Jellyfin Web** no aparecen por ello en clientes nativos de TV; habría que validar cada cliente por separado. [Imagen de la Plantilla](../../stacks/jellyfin/compose.yaml); [anuncio oficial de Jellyfin 12](https://jellyfin.org/posts/jellyfin-release-12.0/); [documentación de Jellyfin Enhanced sobre clientes nativos](https://n00bcodr.github.io/Jellyfin-Enhanced/enhanced/enhanced-features/).

**Recomendación para la vista dentro de Jellyfin:** probar primero la página Requests de Jellyfin Enhanced con la build para Jellyfin 12, Seerr y Radarr/Sonarr configurados, y `DownloadsFilterByUserRequests` activado. Verificar con dos Espectadores sin `REQUEST_VIEW` ni `MANAGE_REQUESTS` que la página y la cola solo revelan sus propias solicitudes, y decidir si el acceso desde Jellyfin Web satisface el uso real de la Instancia. Seerr conserva su propia vista de solicitudes; JellyNotify requeriría una versión para Jellyfin 12 y Seerr Bridge no aporta una página equivalente. [documentación de Requests Page](https://n00bcodr.github.io/Jellyfin-Enhanced/seerr/seerr-features/#requests-page); [filtrado en backend](https://github.com/n00bcodr/Jellyfin-Enhanced/blob/main/Jellyfin.Plugin.JellyfinEnhanced/Controllers/JellyfinEnhancedController.cs); [Seerr RequestCard](https://github.com/seerr-team/seerr/blob/v3.5.0/src/components/RequestCard/index.tsx); [manifest JellyNotify](https://github.com/Rovaal-code/JellyNotify/blob/main/repository/manifest.json); [README Seerr Bridge](https://github.com/monjaka/jellyfin-plugin-seerr-bridge/blob/main/README.md).

El 2026-10-04, el Operador confirmó en esta sesión que consiguió habilitar la página Requests con Plugin Pages. Esta confirmación cubre el acceso a la página; siguen pendientes las pruebas con dos Espectadores y las notificaciones.

## Propuesta de ejecución

1. **Configurar lo ya disponible.** En una Instancia de prueba, activar el agente Web Push en Seerr, activar **Enable Scan** (`syncEnabled`) en los servidores Radarr y Sonarr de **Settings → Services**, entrar como Espectador mediante Jellyfin por HTTPS y suscribir un navegador. Repetir la suscripción en cada dispositivo deseado. La guía oficial define el alta Web Push y el tracker de v3.5.0 exige `syncEnabled`; el Wiring actual lo deja desactivado. [Guía oficial](https://docs.seerr.dev/using-seerr/notifications/webpush/); [tracker](https://github.com/seerr-team/seerr/blob/v3.5.0/server/lib/downloadtracker.ts); [Wiring](../../stacks/wire/wire/steps.py).
2. **Pasarlo a la Plantilla de forma opcional.** Si la prueba funciona, añadir un ajuste optativo a `.env`/`scripts/setup.sh` y sembrarlo solo para configuraciones nuevas o ausentes, siguiendo la regla de Wiring de no sobrescribir decisiones del Operador. Activaría Web Push por API (`POST /api/v1/settings/notifications/webpush`) y, si se desea mostrar progreso, crearía los servidores Radarr/Sonarr con `syncEnabled: true`. Documentar el paso voluntario del Espectador y la particularidad de iOS. [Endpoint Seerr](https://github.com/seerr-team/seerr/blob/v3.5.0/server/routes/settings/notifications.ts); [Wiring existente](../../stacks/wire/wire/steps.py); [contrato de Wiring](../../docs/adr/0002-wiring-only-seeds.md); [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
3. **Acotar una segunda entrega.** Para avisar de fallos, no basta con activar Web Push: v3.5.0 dirige `MEDIA_FAILED` a gestores de solicitudes. Para detectar estancamiento habrá que definir umbrales basados en el estado de Seerr y en las colas de Radarr/Sonarr, conservar el estado para evitar avisos repetidos y enviar solo a `requestedBy`; el `issue-automator` actual usa un único chat de Telegram del Operador, así que no sirve como canal para un Espectador sin vincular su cuenta. Esto requiere diseño y pruebas de comportamiento separadas. [Destinatarios en Seerr](https://github.com/seerr-team/seerr/blob/v3.5.0/server/entity/MediaRequest.ts); [agente Web Push](https://github.com/seerr-team/seerr/blob/v3.5.0/server/lib/notifications/agents/webpush.ts); [issue-automator](../../stacks/extras/issue-automator/main.py); [issue #24](https://github.com/alberba/media-stack/issues/24).

**Validación pendiente en una Instancia real:** probar con dos Espectadores y un Operador la aprobación manual, rechazo, fallo, disponibilidad, autoaprobación y descarga en curso; comprobar que solo el solicitante recibe cada evento dirigido a él y que en móvil se entrega con la app cerrada. La inspección del código no demuestra que el proxy, el navegador y las notificaciones del sistema de una Instancia concreta estén funcionando. [Issue #24](https://github.com/alberba/media-stack/issues/24); [guía oficial](https://docs.seerr.dev/using-seerr/notifications/webpush/).
